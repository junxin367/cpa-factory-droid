## v0.1.14

修复 Factory 返回 `HTTP 403 content_policy_rejected` 时，请求 ID 在 CPA 错误包装后不可见的问题。

### 403 排查

- 优先读取 Factory 错误正文中的 `requestId` 或 `request_id`，其次使用上游 `Request-Id` 或 `X-Request-Id`。有有效 ID 时，客户端错误消息会显示策略错误码和 Factory 请求 ID，并保留上游拒绝原因。
- CPA 常规日志记录 `factory_request_id`，可与 CPA 短请求 ID 对照。不需要开启完整请求日志，新增记录不包含提示词或鉴权信息。
- HTTP 403、出站请求、普通权限错误和重试规则不变。此版本仅便于追踪策略拒绝，不会改变 Factory 的拦截结果。

### 验证

- 本机在 CPA v8.0.52、v8.0.53 配合模拟上游验证客户端收取请求 ID、关闭完整请求日志时的日志关联，以及无有效 ID 和普通权限错误保持原行为。
- 四个平台的安装包须通过发布流水线的 Rust 测试、打包校验和 CPA v8.0.52 集成验证后才公开。

### 升级与回退

在 CPA 插件管理中更新 Factory Droid，并确认插件完成重载。无需修改凭据或模型配置；如需回退，可恢复 v0.1.13 动态库。
