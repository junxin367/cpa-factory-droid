## v0.1.9

移除插件对长请求的总时长限制，补齐模型能力信息，并对齐 CPA 原生凭据的请求、响应和限流处理。缺少图片能力数据的新模型允许转发图片，由上游判断实际支持情况。

### 🛠️ 长请求与模型能力

- 流式和非流式推理不再受原先 180 秒总时长限制，长上下文处理、长思考和持续输出不会因此被插件中断；客户端取消和插件停用时仍正常清理请求。
- 兼容读取旧 `request_timeout_seconds` 字段，但不再执行或写回该限制。
- 使用已核验的官方 Droid CLI 1.2.0 注册表能力快照，并优先采用动态目录中的明确能力数据；修正旧模型使用 `8192` 输出 tokens、`0` 输入预算的默认声明。
- 未知模型不声明猜测的能力值；只有明确不支持图片时才在发送前拒绝图片。管理员明确配置的模型能力、已有模型路由和价格保留。

### 🔄 与 CPA 原生请求处理对齐

- 保留 Factory 必需协议头，合并客户端 `anthropic-beta`、`OpenAI-Beta` 及 SDK `betas` 能力标志，避免新功能被固定名单阻断；鉴权、客户端身份和代理信息仍不透传。
- Factory 请求体封装提前到鉴权后的拦截阶段，随后执行 CPA 的最终 payload override/filter，避免过滤掉的缓存键被重新添加，或用户配置的业务参数被覆盖。
- 错误正文默认读取上限由 32 KiB 提高到 1 MiB，移除错误响应流额外的 2 秒期限和分块数量限制；保留大小保护、截断提示和客户端取消。
- `Retry-After` 支持秒数及 HTTP 日期，不再将等待时间截断到一天。
- 成功 JSON/SSE 响应保留请求 ID、额度等有效响应头，继续过滤逐跳、Cookie 和 CPA 管理的传输字段；最终客户端透传遵循宿主配置。

### 📦 升级与配置

更新插件后确认 CPA 已重新加载新版，必要时重启 CPA。已有 Factory 凭据和模型公共 ID 保持不变。

新增可选配置 `upstream-error-body-limit-bytes`，默认 `1048576`，允许 `1024` 至 `16777216` 字节。旧配置不需要手工删除 `request_timeout_seconds`。

响应头是否发给客户端仍由 CPA `requests.passthrough-headers` 控制，插件不会强制打开该开关。管理员的 payload 规则可覆盖默认请求封装，应确保最终参数符合目标上游接口。

升级前按 README 备份 CPA 的 `auth-dir`、插件 `data-dir` 和动态库。回退时恢复对应备份及旧版动态库；v0.1.8 会恢复旧版的请求时限和错误读取行为。

### 🧪 验证与边界

- 31 项 Rust 单元测试通过。
- Windows 本机分别使用 CPA v8.0.47、v8.0.52 运行 145 项模拟上游检查，覆盖三协议 JSON/SSE、长请求、取消、beta、响应头、慢错误正文、限流日期、payload 最终优先级和未知图片能力。
- 发布流程对 Windows x64、Linux x64、macOS Intel、macOS Apple Silicon 分别运行 Rust 测试、构建和实际 CPA v8.0.52 宿主检查，全部成功后才公开四平台安装包、`checksums.txt` 和 `latest.json`。
- 推理回归使用本机模拟上游，不代表所有真实 Factory beta 或模型视觉功能均已验收。图片及未知能力标志的实际支持情况由 Factory 决定。
- 本版不新增跨协议转换、WebSocket、服务端 fallback 或宿主尚未提供的凭据级额度冷却接口。
