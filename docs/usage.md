# CPA 原生用量与官方额度

## 请求统计

插件保留上游原生 usage，由 CPA 提取请求次数、成功/失败、Token 和缓存等数据。
`usage_plugin` 能力关闭，不再额外写入插件账本，也不会主动消费 CPA 用量队列。

```yaml
observability:
  usage:
    usage-statistics-enabled: true
```

CPA-Manager-Plus 完整模式负责采集并持久化原生请求历史；同一 CPA 用量队列只由一个 Manager 消费。费用统一在该管理端的模型价格表中计算，核对实际计费模型 ID 与价格键。
新部署的 Manager 从运行后开始采集，不会自动导入插件之前的验证记录。

## 官方额度

CPA 调用插件的 `quota.fetch`，后者读取 Factory `/api/billing/limits`。
返回标准 5 小时、7 天、30 天滚动窗口、Droid Core 窗口及官方额外 USD 余额。
比例、重置时间和余额缺失时保持未知；查询失败返回错误，不当成零额度或成功刷新。

额度响应不再包含插件请求数、加权 Token、预算、容量预测或自算费用。
通用管理端不知道额度池对应的完整模型集合时，不据此计算该池的官方容量。

CPA 官方管理端已有通用插件额度卡片；CPA-Manager-Plus v1.14.10 可通过 v0.1.3 插件自带的页面增强显示标准窗口。打开一次 Factory Droid 页并连接即可激活，无需应用独立前端补丁；整页刷新后需重新激活。

v0.1.4 的增强另外通过 Manager 的 `monitoring/account-window-usage` 读取窗口内此凭证的 CPA 请求，保留 Manager 统一计费口径；该区间统计包含此凭证的所有模型，不能解释为官方 Standard 池的精确账单。容量预测仅在边界与样本有效、标准额度未耗尽且未出现 Core 用量时，按 Manager 的额度比例算法估算。Manager 之外的使用不在统计内；预测不是官方账单或官方总容量。缺失范围、未匹配数据和查询失败均不当作零。

## 旧数据

历史插件账本和价格字段保持可读取，不自动删除。它们不会继续增长，也不会伪造成 CPA 新请求。
此处的官方额度百分比不等于请求统计或官方账单。
