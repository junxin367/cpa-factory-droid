# 用量、官方窗口与估算

页面把官方限额、官方 FSC 消耗和本插件用量分开。它们的来源、单位与时间范围不同，不能互相相减或替代。

## 三种数据来源

| 数据 | 来源 | 含义 |
| --- | --- | --- |
| 官方限额 | Factory 私有 billing limits | Standard / Core 各官方窗口的已用比例、剩余比例和重置时间 |
| 官方额外用量余额 | 同接口的 `extraUsageBalanceCents / 100` | 官方返回的 USD 余额，不是 token 总额 |
| 官方消耗 | Factory 公开个人 Analytics | 已用 FSC，不是剩余额度 |
| 本插件业务用量 | CPA `usage.handle` | 只含经过本插件的已观测请求 |
| 基础验证用量 | 明确确认的模型测试 | `kind=validation`，与业务调用分列并计入总预算 |

API Key 能否读取官方接口以本次响应为准。无权限、查询失败或未知格式显示不可读取/未知，不显示成零余额。真实 Factory 账号的上述能力尚未完成本项目验收。

账号卡片顶部的请求、Token、费用、成功率共用 `account.usage.window_start/window_end`，默认 UTC 自然月或配置的自定义范围，包含 validation；它们是本周期本插件已记录值，不是账号全历史。最近请求条取该范围的最近子集。下方官方额度行的 `period_stats` 使用各自官方窗口，两者不能混作同一个周期。

## 后端报表与预算 API

页面以账号管理和账号卡片为入口，不提供独立用量或预算 Tab。后端仍按 UTC 自然月或配置的自定义半开区间 `[开始, 结束)` 提供报表与预算数据。

受管理认证保护的 `GET /v0/management/plugins/factory-droid/usage` 可加 `account_id` 和 `kind=all|inference|validation` 查询参数。窗口和预算由 `/settings` API 读取/更新；这不是页面上新增的设置入口。请求总数包含成功和失败；成功但没有 usage 的请求只计次数，不估算 token。

本地输入统一为“含缓存读取及缓存写入”：Anthropic 的原始 input 不含缓存，在入账时加入一次；Responses / 标准 Chat 已含缓存子集，不再叠加。reasoning 已含于 output，不重复相加。原始总 token 为 input + output。

加权 token 使用当前请求记账时的倍率：

```text
（input - cache_read - cache_write）× 输入倍率
+ cache_read × 缓存读取倍率
+ cache_write × 缓存写入倍率
+ output × 输出倍率
```

美元估算分别使用上述四部分对应的 USD / 百万 token 价格。账号价格覆盖优先于全局价格；实际使用某部分 token 却缺少该项价格时，不生成完整美元金额。历史请求保存当时的结果，不用今天价格重算。

全局预算是用户设置的加权 token 参考值，包括业务和基础验证消费；请求类型筛选不会把验证从预算中扣掉。预算不重复套在单账号上，也不强制拦截请求。任何成功请求缺 usage 时，预算消费完整性不足，剩余预算保持未知。

## 每个官方窗口的 M / $

账号额度卡片中，每个官方窗口另有 `period_stats`。它使用**该账号、该明确额度池、该官方窗口的 `[window_start, window_end)`**，不受全局报表窗口影响。

页面按一个官方周期一个紧凑行组展示：

1. 周期标签、官方剩余百分比、细进度条。
2. 蓝色组：本插件该周期已用 USD / 已用 M Token。
3. 紫色组：带“≈”的预计周期总 USD / 预计周期总 M Token，以及重置倒计时。

主行已用 USD 仅在 `status=available`、`cost_complete=true` 且 `estimated_cost_usd` 有效时展示，缺价只显示“—”。主行 M 还要求 `usage_complete=true`、没有缺 usage 或无效时间记录，否则为“—”。预测必须对应同一账号/池/官方周期且状态为 estimated，缺失的费用或 M 分别显示“—”。

覆盖 partial 时，记录本身完整的数值仍可展示，覆盖和已知小计字段保留在 API。蓝色显示已用，紫色显示预计总量；`group=core` 且 `window_key=fiveHour` 的 Droid Core 5 小时行隐藏，后端统计和预测字段保留。

窗口边界必须来自官方明确起止时间，或来自可信机器窗口键对应的时长；只知道重置时间、显示名称或一段人类描述，不足以猜完整周期。边界未知、未开始或已过期时，统计状态为 unknown，数字为 null。

额度池取 `quota_pool=standard|core` 及可信 `quota_pool_source=factory_registry|explicit_config`。新建手工路由默认为 unknown，不按模型品牌、名字或 API 提供方推测。旧账本没有可信池来源的记录迁移为 unknown，保留 token / 费用，不重分配到任意池。

| 字段或页面含义 | 如何理解 |
| --- | --- |
| `total_mtokens` / M | 本插件在此账号/池/窗口内已测得的原始 token / 1,000,000 |
| `known_cost_usd` | API 中已有完整单次价格的请求合计，不替代卡片主行完整费用 |
| `estimated_cost_usd` | 仅在该统计集合无缺价、无缺 usage 等不完整情况时提供，否则 null |
| `unpriced_requests` | 有关请求没有完整价格 |
| `missing_usage_requests` | 成功请求缺少可用 usage；API token 仅为已测得部分，主行 M 保持未知 |
| `unclassified_requests` | 此窗口内额度池未知的记录；不计入任何池的 token / USD |
| `validation` | 同一窗口内验证请求的子合计，已包含在主合计中，不要再加一次 |

`coverage` 说明本插件连续记录和保留范围：

- `complete`：本插件的连续观测/保留起点覆盖此周期开始至今。
- `partial`：本插件从周期中途开始记录，或有其他明确覆盖缺口。
- `unknown`：没有足够的边界或连续记录证据。

覆盖完整仍只代表本插件的记录，不代表 Factory 全部客户端。`coverage`、`usage_complete`、`cost_complete` 是不同条件；有 M 数值不证明 token 完整，有“已知美元部分”不证明完整费用。零值不能消除缺失计数或未知范围。

## v2 容量预测

通过账号“验证 / 刷新”取得官方额度快照。预测以两次快照之间的本地业务与验证记录作样本，必须满足：

1. 同账号、同明确额度池、同机器窗口键、精确相同起止边界。
2. 两个样本都是 v2，属于同一账本代次；采样顺序有效，当前窗口尚未结束。
3. 官方已用比例增加至少 0.5 个百分点，期间至少 100 个原始 input + output token。
4. 期间成功请求的 usage 完整，没有未知池或无效时间记录。

```text
估算总 token = 样本 token / 已用比例变化（百分点）× 100
估算剩余 token = 估算总 token × 官方剩余比例
```

M 值再除以一百万。美元总/剩余量按同一区间完整的本地费用同比外推；区间内缺价格只让美元未知，区间外早期缺价不会永久污染后续完整样本。官方剩余比例未知时不生成剩余量。

账本裁剪、窗口重置、代次变化、旧样本版本、计数不连续、样本不足、缺 usage 或未知池都会使相应预测未知。保留最近 40 天、最多 12,000 条快照；账本保留最近 400 天。预测不使用 FSC、用户预算或模型品牌猜测，也不提供耗尽日期。

其他客户端消费、样本期间模型组合改变和官方百分比精度都会影响推算，因此结果不是官方 token 或美元余额。

## Analytics 日期范围

个人 Analytics 返回 UTC 自然日汇总，官方 startDate / endDate 为含首尾日期；插件把自己的半开窗口正确换算成日期请求：

- 当前自然月只查询到今天，返回实际截止时间及 partial 状态，未来日期不算作已完整覆盖。
- 自定义子日窗口不能得到精确官方日统计，显示不可读取，不能假算成 0。
- 早于 2026-01-14 的起点不作为完整可查询窗口；未来尚未开始的窗口保持未知。
- 超过 90 天的范围按最多 90 天、互不重复的日期段请求；一段失败不把部分结果冒充完整结果。
- 返回日期重复、越界、无效，或 FSC 字段非法时拒绝把结果当作完整用量。当前日数据可能继续变化。

这些规则只影响官方 FSC 的查询，不改变本地账本或每官方窗口统计。Analytics 还需要实际套餐和角色权限；消费金额不用于推导官方剩余量。
