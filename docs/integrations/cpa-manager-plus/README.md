# CPA-Manager-Plus 通用插件额度适配

## 原生模型列表与禁用项

插件增强同时加载 `manager-models.js`，将 Factory 的模型定义查询转到插件自己的完整目录接口。Manager 继续用自己的规则计算“全部 / 可用 / 已禁用”，已排除的模型不会因为从运行目录中消失而丢失展示。适配只重定向同源、GET、`factory-droid` 的模型定义请求，保留原管理端鉴权，其他提供商和推理请求沿用原路径。

默认目录来自 Factory 官方模型页面，在模型页打开或刷新时最多每 3 分钟检查一次；不依赖手工填写 CLI 路径。显式配置 CLI 时仍以 CLI 为准。首次激活和自动加载方式与下面的额度增强相同。

## v0.1.3 起：通过插件页激活

更新 Factory Droid 后，在 Manager 侧边栏打开一次 **Factory Droid** 并连接当前管理端，看到“原生额度已启用”后返回凭证页，即可在卡片、列表和详情抽屉中刷新官方标准额度。脚本和样式随插件动态库发布，不需要单独部署 `management.html` 或安装 JS Handler。

前提是插件 iframe 与 Manager 同源，且允许访问父页面。脚本加载到父页面后持续工作，普通切页不会失效；浏览器整页刷新、退出登录或切换管理连接后，重新进入插件页激活。未保存管理密码时在插件页手工连接即可，不要求保存密码。

v0.1.4 可在插件页开启“自动加载额度增强”。Service Worker 仅在每次导航到 `/management.html` 时读取原页面，并加入同源启动模块；不缓存 HTML，不截获额度、统计或推理接口，不保存密钥。启动模块只观察当前页面已经成功的同源管理请求来复用本次登录授权，因此无需为了自动加载而勾选“记住凭证”。

首次打开和启用仍是浏览器要求；新浏览器或清除网站数据后需要重新启用。开关可撤销注册，插件资源 404/410 时自动注销，资源暂时不可用时返回原页面。与已有其他 Service Worker 冲突、跨源、非安全上下文或浏览器策略不允许时，保持手动激活方式。此机制不修改服务器上的 Manager 文件。

展示限定为 Factory 官方标准 5 小时、7 天和月额度。CPA / Manager 原有总体用量继续使用自身数据，内置额度风险筛选和批量额度刷新没有被改写。额度结果按凭证和管理连接隔离，不把令牌写入新存储项。失败保留上次结果并提示重试。

Factory 卡片在“优先级”左侧显示套餐名称，沿用 Manager 的蓝色套餐标签样式。套餐随额度查询更新：优先使用额度接口的 `planType`；当前接口未返回该字段时，读取官方账单页使用的 `/api/app/auth/me` 中的 `organization.subscription.factoryTier`，例如 `pro_plus` 显示为 `Plus`。套餐接口无权限、查询失败或未返回名称时不显示标签，已有额度仍正常展示；套餐与额度共用凭证隔离、3 分钟刷新间隔和当前标签页快照。

## v0.1.5 起：进入页面刷新与相对重置时间

不再定时轮询额度。进入凭证页、从其他提供商筛选切回时，对当前显示的 Factory 凭证检查一次：距离上一次查询尝试不足 180 秒就跳过，超过间隔则查询。官方已知周期结束时立即隐藏旧周期用量，并在满足 180 秒间隔后补一次官方查询；同一周期失败或返回未变化数据时不反复重试。后台标签页暂停周期检查，离开页面及退出登录取消计时器。普通 DOM 重绘和展开抽屉不增加查询。手动点击额度刷新、抽屉刷新历史或页面刷新按钮可立即查询，手动查询也会更新冷却时间。

当前标签页使用 `sessionStorage` 保存 3 分钟内的安全快照，键由当前管理连接和授权的 SHA-256 派生，内容不含密钥。整页重载后仍遵守冷却间隔；退出登录或切换连接清理快照。浏览器禁用存储或不提供 Web Crypto 时退回页面内存缓存。

月窗口显示名称统一为“月额度”，保留 Standard 额度池语义；旧快照名称会直接迁移，不因改名重置刷新间隔。卡片消耗使用蓝色折线图标、预测使用紫色趋势图标，金额和 Token 采用 Manager 的主次文字颜色。

卡片重置时间移到进度条下方、用量行右侧，以“n 天后 / n 小时后 / n 分钟后”显示；抽屉放在窗口标题行。悬停显示包括年份、月份、日期和时分秒的完整重置时间。采用 Manager 原生相对时间的向下取整规则。

预测算法和可用性规则未改动：仍按当前窗口已用量除以额度已消耗比例估算。多个窗口的已用量和消耗比例相同时，预测结果可以相同，不通过窗口时长强行放大数值。

## v0.1.4 起：复用 Manager 窗口统计

插件通过管理接口 `POST /v0/management/plugins/factory-droid/accounts/quota-windows` 返回经过脱敏、绑定凭证名称和 `auth_index` 的窗口元数据。该接口只查询 Factory 官方额度，不记录账本或价格。CPA 通用额度接口的固定结构无法承载窗口起点、观测时间等字段，因此保留原生额度接口，同时增加此专用适配接口。

前端将凭证的真实 `factory-droid` 类型、文件名、索引及区间传给 Manager 的 `POST /v0/management/monitoring/account-window-usage`。请求数、Token、成功率和费用均使用 Manager 返回值，Manager 改价后再次刷新即采用新价格。卡片显示当前区间的已用费用 / Token 和可用预测；抽屉展示前期、当前、预测三列。抽屉“刷新历史”同时更新这些数据。

窗口规则：

- 优先读取官方窗口起止时间。只有重置时间时，用官方窗口类型的 5 小时、7 天、30 天时长推导起点，标记为“由重置时间推导窗口”。
- 缺少可信边界或窗口已到期时不查询该区间；未匹配到请求显示“窗口统计暂未采集”，不将缺失数据当作零。
- 首次进入只能比较“前一等长区间”。当前页面实际观测过前一周期边界后，才标为“上个窗口用量”；不凭空补造历史周期。
- 用量统计范围是该凭证在此区间的全部 CPA 请求。Standard 优先消耗，不能仅凭模型名称将历史请求划为 Standard / Core。存在 Core 用量、额度池信息不全或标准额度耗尽时，保留区间用量但不显示容量预测。
- 预测沿用 Manager 的 `estimateWindowUsage` 当前用量除以额度已消耗比例、请求/Token 取整和费用两位小数规则。它只是基于本 CPA 样本的估算，不是官方账单或额度总价；本插件不使用前一等长区间冒充真实上一周期来兜底预测。
- 只在额度与用量来自同一次观测、数据完整且比例有效时预测。请求失败、窗口重置、观测过期、凭证或管理连接变更后，不套用旧用量生成新预测。

适配参考 CPA-Manager-Plus v1.14.10 的 `accountWindowUsageRows.ts`、`accountQuotaWindowUsagePresentation.ts` 与 `estimateWindowUsage.ts`；费用完全由 Manager 服务计算。原项目 MIT 授权见 [LICENSE](LICENSE)。

## 历史源码补丁（可选）

适用版本：`seakee/CPA-Manager-Plus v1.14.10`，提交 `a67ed8834a914ab24c36d2490fa6bb6d4166724c`。
以下 `plugin-quota.patch` 是先前独立维护前端时使用的方案，包含新增模块，未修改 Manager Server 和 CPA 内核。新插件的页面增强不依赖此补丁，用户无需执行以下构建与安装步骤。

## 修复范围

原版账号页只为固定提供商显示额度刷新控件。本补丁读取原生凭据的 `supports_quota`、`quota_provider` 和可选的 `quota_plugin_id`，通过 CPA 原生插件额度接口刷新。

卡片、批量栏与详情抽屉共用原生刷新流程；主卡片显示第一个额度组的前三个窗口，详情可查看全部窗口。
额度请求和缓存绑定当前凭据及连接，未知值不会当作零。
插件返回的组名不能证明其对应的完整模型集合，因此不把整账号请求量冒充某个额度池的用量预测。

## 构建与安装

在干净的对应上游源码中执行：

```powershell
git apply --check E:/code/junes/github/cpa-factory-droid/docs/integrations/cpa-manager-plus/plugin-quota.patch
git apply E:/code/junes/github/cpa-factory-droid/docs/integrations/cpa-manager-plus/plugin-quota.patch
npm ci
npm run type-check
npm run build
```

将 `apps/web/dist/index.html` 复制到 Manager 安装目录的 `management.html`，备份并在 `config.json` 中合并：

```json
{
  "panelPath": "./management.html"
}
```

重启 Manager，再刷新浏览器页面。本机安装目录为 `E:/code/junes/github/cpa-manager-plus-local`，入口为 `http://127.0.0.1:18317/management.html`。
升级 Manager 时应重新核对补丁，不直接用旧 HTML 覆盖不同版本的页面。
