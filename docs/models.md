# 账号、候选模型与发布

Factory 身份验证、CLI 候选、基础调用验证和 CPA 发布是四种不同事实。身份有效不代表所有模型可用；CLI 列出模型也不代表该账号有调用权限。

## 新建账号

在账号页点击“新建”，在约 640px 的右侧主抽屉填写名称和 Factory API Key。服务端先验证身份并建立草稿。点击“获取模型”打开独立候选弹窗，搜索、多选后“添加所选”回到主抽屉继续配置。

主抽屉按“模型名称 → 账号调用别名”紧凑展示选择，价格按需展开，再通过测试菜单测试并查看结果，固定底部“创建”保存账号。模型选择弹窗不自行创建账号或发送推理。可以跳过模型选择和测试，直接保存零模型账号。

模型列表同时展示 CLI 候选和已有的明确配置。Sonnet 5.5 等模型若因 CLI 功能开关未出现在目录中，仍按已有配置列出并标记“待验证”，选择后使用手工配置来源进行基础测试，不伪造 CLI 快照或权限证明。目录已明确禁用、弃用或过期的候选不会通过补充列表重复出现来绕过限制。

可以直接以零模型创建账号，再从账号卡片读取额度。也可以保存包含待验证或测试失败模型的账号，之后再处理；这些模型不会因为保存成功而发布。

创建前，Key 只留在插件内存草稿，尚未写 CPA auth 文件。草稿创建后固定 30 分钟失效，每个插件进程最多同时保留 32 个；取消主抽屉中的新建、删除草稿或插件停止/重启会清除。关闭候选选择弹窗仅回到主抽屉。已有 Key 不会回填到浏览器表单。更换 Key 需要新建草稿。

## 获取候选或手工选择

“获取/刷新候选目录”先确认身份，再调用管理员配置的官方 Droid CLI `droid.list_models`。它不建立推理会话、不测试模型、不发布模型。插件不提供臆造的 Factory HTTP `/models` 发现接口。

**候选仅是选择来源。** 本次独立验证中，官方 CLI 在故意无效的 Key 下仍可返回 60 个模型，因此不能将候选数量、目录读取成功或 CLI 的模型元数据当作账号权限证明。`selection_source=official_droid_cli` 也只说明从何选择。

获取目录时，插件先保留已有的精确上游 ID 配置，再为新模型补齐原生路由：官方目录中的 Anthropic 使用 Messages，OpenAI / xAI 使用 Responses；Factory 托管模型按已核对的官方 CLI 注册表确定协议与实际提供方，不按模型名的前缀猜测。新路由仅进入可选配置，不自动允许账号调用，也不自动发布。

已核对的 Fast / Ultra Fast 变体会补齐官方要求的 `speed`、`service_tier` 和 Anthropic beta 请求头。客户端提供冲突值时明确报错，不降级成标准模型。原生请求正文、工具和思考内容仍按原协议传递。

| 候选情况 | 处理 |
| --- | --- |
| 有明确、启用的原生路由 | 可选择并主动基础测试 |
| disabled / deprecated / custom / router 或元数据无效 | 阻止选择和验证，不能用手工路径绕过已知限制 |
| 官方目录具有可确认的原生路由 | 自动补齐模型配置，可选择、测试并添加；保留既有自定义配置 |
| Google 原生协议或无法确认的托管路由 | 显示具体限制，不转换协议；未知路由仍需明确配置 |
| 目录过期或刷新失败 | 旧结果保留并标 stale；不能作为新鲜 CLI 选择继续新增 |

成功候选快照有效期 5 分钟。失败不刷新上次成功时间，也不悄悄用内置定义冒充成功发现。刷新时出现旧请求迟到，不会覆盖较新的快照。

协议依据：Factory 官方 Available Models / BYOK 文档，以及本地核对的 `@factory/cli-win32-x64@1.2.0` 注册表（EXE SHA256 `b075e952982d0b3c731e875dfd4e95c835c4d1a8d9e46c791636ebd8116fd754`）。注册表将 `anthropicFastMode` 对应为 `speed=fast` 与 `fast-mode-2026-02-01`；OpenAI 快速变体分别使用 `priority`、`ultrafast`。目录元数据仍不作为账号权限证明。

未配置 CLI 时，使用“手工选择已有明确路由”。此时 `selection_source=manual`，仍须基础测试；不会标成 CLI 已确认。CLI 的独立安装与 `droid-cli-path` 配置见 [README](../README.md)。

## 显式测试与允许

草稿中先选择模型，再确认额度消费并测试；已保存账号使用卡片底部“模型管理”图标进入独立抽屉，管理获取、基础验证、允许和同步。页面不保留独立用量、模型或帮助 Tab。

每次测试只发送一条固定的原生短文本请求，要求回复 `OK`，输出上限 128 token；不接受用户自定义 prompt、tools 或请求体。它可能消耗额度和费用。批量测试是对多个模型分别执行，每个模型一条请求；再次主动测试可能再次消费。

测试必须得到相应原生完成状态和非空文本。仅 HTTP 2xx、空内容或不完整协议终态不会允许模型。成功证据的 `verification_source=factory_basic_call`，绑定当前精确凭据、身份/组织/区域及当前模型路由；只证明当时这条基础调用成功，不证明工具、图片、长上下文等全部能力或未来权限。

测试以 `kind=validation` 独立记账，不伪造一份业务 usage。成功/失败测试可分别查看，验证纳入全局预算统计；已发出请求即使随后取消、删除草稿或验证结果失效，用量记录仍保留。失败或缺 usage 时保留状态与次数，不补 token 或费用，也不据此判断官方收费为零。

草稿测试成功后仍未发布模型，必须创建账号。已有账号的“验证并允许”成功后会保存允许意图，并等待 CPA 注册确认。

## 何时实际发布

期望生效集合取以下条件的交集：

1. 账号存在、启用且身份有效。
2. 全局模型路由存在并启用。
3. 该账号有允许该模型的意图。
4. 当前凭据/组织与路由对应的基础调用验证有效，且没有候选明确禁用等阻止原因。

`model.for_auth`、请求门禁、执行器、固定账号 ID 和管理页都使用同一集合。旧账号或旧模型定义没有当前验证证据时保留数据，但不会自动发布。

| 状态 | 含义 |
| --- | --- |
| 已选择 / 待验证 | 保存了选择，尚不能调用 |
| 已基础验证 / 已允许 | 具备对应证据和意图，还需检查其他生效条件及 CPA 同步 |
| `effective=true` | 当前期望纳入目录 |
| `published=true` / `publication_status=published` | CPA 已确认实际注册 |
| `pending_add` / `pending_remove` | 期望集合与 CPA 当前集合不同，等待发布或撤销同步 |
| `unknown` | 暂时无法确认 CPA 实际目录，不能冒充已发布 |

服务端等待 CPA 的模型回调和实际 ID 集合确认，通常最多等待 5 秒。若返回 `503 catalog_refresh_incomplete`，配置或验证结果可能已保存，**使用“重试发布同步”**；它只重新同步 CPA，不发推理、不重做测试。

草稿创建遇到同步错误时，保留原草稿 ID 重试“创建同步”；已保存账号不会重复创建，也不重复测试。不要为了发布同步错误连续点击付费测试。

撤销允许会注销该账号的共享/固定目录；另一个账号仍允许同一模型时，共享 ID 继续由该账号提供。凭据/组织/路由变化或 401/403 会使相应证据失效；暂时的 429、5xx、超时可保留仍匹配的既有成功证据，页面另记本次错误。恢复候选或重新启用路由不会替代所需验证。

## 账号别名与四项价格

新建草稿中可以为每个选中模型设置：

- 账号调用别名：仅改变 `factory/<account-id>/<alias>`，不创建全局别名，也不改变原生协议。
- 未缓存输入、输出、缓存读取、缓存写入四项美元单价：单位为 USD / 百万 token，仅覆盖该账号的本地估算。

别名限 1–80 个字母、数字和 `._-`，不包含 `factory/`，不能占用同账号其他模型的原始后缀或别名。价格留空 / null 继承全局，数值 0 则是明确配置零价格。修改草稿别名或价格保留仍有效的验证，不自动重新收费测试。

全局共享 ID 仍为 `factory/<模型后缀>`；固定账号 ID 使用实际返回的 `pinned_models`，不要手工猜测。两种 ID 都只在其账号模型已有效发布后可用，并遵循 [同一原生协议](protocol.md)。

## 并发与持久化

并发发现、验证、撤销、删除和路由变更使用操作代次检查，较早的结果不能恢复已撤销或已删除的模型。它不等于“同一模型重复点击只消费一次”：每次已经发出的验证请求仍各自可能消费。

已保存账号的 Key 在 CPA auth 存储，账号状态、候选、验证记录、价格覆盖和本地账本在插件 `data-dir`。目录状态以 CPA 实际确认值为准，不把磁盘期望状态等同于发布成功。写盘失败返回错误；看到内存中的数据不代表已持久化。

单个数据目录供一个 CPA 进程使用，未提供多进程写入锁。每次账本更新写完整 JSON，经同步临时文件后原子替换；历史数据增长会增加写盘工作量。损坏文件应保留并从备份恢复，不通过清空账本制造成功状态。

## 保留的管理 API

以下路径均以 `/v0/management/plugins/factory-droid` 为前缀并需要管理认证；保留 API 不表示存在对应独立页面或 Tab。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /accounts/models?account_id=...` | 当前账号的候选、验证、允许及实际发布状态 |
| `POST /accounts/discovery` | `{id}`，刷新候选，不推理 |
| `POST /accounts/models/verify` | `{id, model_id, confirm:true}`，显式付费基础验证；CLI 选择另带当前 `discovery_snapshot_id` |
| `DELETE /accounts/models/allow` | `{id, model_id}`，撤销允许 |
| `POST /models/reconcile` | `{}`，只重试发布同步 |
| `GET /settings` / `PUT /settings` | 读取/保存完整路由与估算设置 |
| `POST /drafts` / `DELETE /drafts` | 创建身份草稿 / 取消草稿 |
| `PUT /drafts/models` | 完整选择集及账号别名、四项价格覆盖，不推理 |
| `POST /drafts/models/test` | 对已选模型显式 `confirm:true` 测试 |
| `POST /drafts/commit` | 以原草稿 ID 保存或重试创建同步，不重复测试 |

路由中的 `protocol`、上游 ID 和提供方必须明确配置。更新 `/settings` 时先读取现有完整设置，保留其他路由和配置；不能用单条模型覆盖已有集合。路由变化会使对应旧验证失效，单纯价格或倍率修改不会自动发送推理。
